GlobeSync — Enterprise Video Translation Platform

Architecture overview & end-to-end processing pipeline — v1.2.0

What is this project?

GlobeSync is a production-ready, cloud-agnostic platform that takes a source audio or video file and produces a fully dubbed, lip-synced translation in a target language. The platform automates every step: speech-to-text, speaker diarization, context-aware translation with duration matching, voice cloning, TTS synthesis with audio retiming, and neural lip-sync rendering via AI models — all orchestrated through an async task queue.

End-to-End Processing Pipeline

1
Project Creation & Media Upload
User creates a project (source + target language) in the Next.js UI. Project metadata is saved to IndexedDB. The user uploads an audio/video file (up to 100 MB direct; larger via resumable chunked upload). FastAPI validates the file (magic-byte inspection, MIME detection, SHA-256) and stores it in S3 / GCS / MinIO, persisting a MediaFile record in PostgreSQL.
Next.js UI FastAPI /upload Object Storage
2
Audio Extraction & Pre-processing
A Celery task (stt_diarize queue) downloads the raw media and uses FFmpeg to demux it into a 16 kHz mono WAV optimised for STT (<30 s for 4 GB files). The extracted audio is then noise-reduced (noisereduce library), loudness-normalised to −20 LUFS, and chunked into manageable pieces for files longer than 20 minutes.
Celery: stt_diarize FFmpeg −20 LUFS / VAD chunking
3
Speech-to-Text & Speaker Diarization
Each audio chunk is sent to Deepgram Nova-2 for transcription with speaker diarization and word-level timestamps. Results are parsed, normalised, time-offset-merged across chunks, and persisted as Transcript + TranscriptSegment rows in PostgreSQL. Real-time progress (10 → 100 %) is published to a Redis Pub/Sub channel and streamed to the UI via SSE.
Deepgram Nova-2 PostgreSQL Redis SSE
4
Context-Aware Translation with Duration Matching
A second Celery task (translation queue) loads all transcript segments and runs GPT-4o (or Google Cloud Translation) in parallel batches of up to 10 concurrent requests with a sliding context window for coherence. Each translated segment is measured for speech rate and iteratively rewritten (condensed or expanded) until the translated text fits within ±10 % of the original segment duration. Results are stored as Translation rows with duration ratio and speed-adjustment metadata.
OpenAI GPT-4o Google Cloud Translation (alt) Celery: translation ±10 % duration loop
5
Voice Cloning & TTS Synthesis
The tts_clone Celery task harvests 30–90 s of clean audio per speaker from the original media and calls ElevenLabs Instant Voice Cloning to build per-speaker VoiceProfile records. All translated segments are then synthesised concurrently (up to 10 parallel requests) using ElevenLabs Multilingual v2. Each generated audio clip is uploaded to cloud storage and recorded as a GeneratedAudio row.
ElevenLabs Multilingual v2 Celery: tts_clone Voice cloning (per speaker)
6
Audio Retiming & Master Dub Assembly
Each synthesised segment is time-stretched with FFmpeg atempo (0.75×–1.35× speed range) to hit its exact original timestamp slot within ±100 ms. De-clicking filters are applied at splice points. All retimed clips are mixed into a single master dubbed audio WAV that matches the exact original video duration and uploaded to cloud storage.
FFmpeg atempo Celery: audio_retiming ±100 ms precision
7
Neural Lip-Sync Rendering
The lipsync_render Celery task slices the original video into per-segment clips, extracts a keyframe and runs face detection to identify suitable frames. For each speech segment containing a detected face, it calls Replicate (LivePortrait or Wav2Lip) to generate neural facial animation synchronised to the dubbed audio. A/V sync drift is measured for each rendered segment; segments with no detectable face fall back to a straight audio mux. Per-segment quality scores and face metadata are persisted as FrameMetadata.
Replicate LivePortrait / Wav2Lip Celery: lipsync_render AV drift measurement
8
Video Reconstruction & Export
All rendered clips are stitched back into the original video timeline with the master dubbed audio muxed in. SRT/VTT subtitles are generated from translated segments and either burned in or attached as soft subtitle tracks. The final video is H.264-encoded and uploaded to cloud storage as the deliverable exports/{project}/{lang}_translated_master.mp4. The UI is notified via SSE and the project status is updated.
FFmpeg H.264 Celery: mux_export SRT / VTT subtitles Cloud Storage export
✓
Translated Video Ready
The user receives a dubbed, lip-synced MP4 with subtitle tracks — spoken in the target language with original speaker voices cloned — delivered via a signed cloud storage URL.

Key Design Decisions

Duration-Matching Feedback Loop

Every translated segment is iteratively rewritten until its estimated spoken duration fits within ±10 % of the original. This prevents audio segments from running over their video window, eliminating the need for aggressive speed changes.

Per-Speaker Voice Cloning

The platform harvests 30–90 seconds of clean speech per speaker from the original video and creates an ElevenLabs voice profile. All TTS segments for that speaker are then synthesised with their cloned voice, preserving vocal identity across languages.

Graceful Lip-Sync Fallback

If no face is detected in a segment (e.g. B-roll, text cards, close-up of hands), the platform skips the expensive neural rendering call and simply muxes the dubbed audio into the original video slice — ensuring the pipeline never blocks on segments that don't benefit from lip-sync.

Cloud-Agnostic Storage Abstraction

All object storage calls go through a single storage_service abstraction layer that supports S3, GCS, and MinIO interchangeably — deployable on AWS, GCP, or a local Docker Compose stack with zero code changes.
